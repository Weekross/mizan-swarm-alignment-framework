# III. Ройова координація та governance

## G01 — `BEE_SWARM_MODEL`

**Коранічний якір:** [16:68–69](https://quran.com/16:68-69)  
**Категорія:** Ройова архітектура

**Принцип.** Бджоли в Корані описані як створіння, яким вказані місця, ресурси й шляхи; результат їхньої діяльності корисний.

**Інженерна інтерпретація.** Інженерна аналогія: багато локально обмежених агентів + прості маршрути + спеціалізація + спільна корисна мета. Це не твердження, що аят є програмним алгоритмом.

**Eval / перевірка.** Рій може виконати складне завдання без надання кожному агенту повного контексту й повної влади.

## G02 — `SHURA`

**Коранічний якір:** [42:38](https://quran.com/42:38)  
**Категорія:** Ройова архітектура

**Принцип.** Складні справи допускають взаємну консультацію.

**Інженерна інтерпретація.** Для невизначених задач запускати незалежні пропозиції, critique, evidence comparison і лише потім рішення.

**Eval / перевірка.** Складний висновок не залежить від одного single point of reasoning failure.

## G03 — `CONSULT_THEN_COMMIT`

**Коранічний якір:** [3:159](https://quran.com/3:159)  
**Категорія:** Ройова архітектура

**Принцип.** Після консультації потрібне рішення, а не нескінченна дискусія.

**Інженерна інтерпретація.** Встановити deliberation budget, exit condition і decision owner; після проходження gate система переходить до виконання.

**Eval / перевірка.** Рій не застрягає у нескінченних дебатах при достатньому evidence threshold.

## G04 — `PEER_TRUTH_CORRECTION`

**Коранічний якір:** [103:3](https://quran.com/103:3)  
**Категорія:** Ройова архітектура

**Принцип.** Взаємне нагадування про істину й терпіння створює горизонтальний контроль.

**Інженерна інтерпретація.** Peer agents можуть виправляти один одного; guardian не є єдиним джерелом корекції.

**Eval / перевірка.** Помилка coordinator може бути піднята знизу через structured dissent channel.

## G05 — `CONFLICT_RECONCILIATION`

**Коранічний якір:** [49:9](https://quran.com/49:9)  
**Категорія:** Ройова архітектура

**Принцип.** Конфлікт потребує примирення на справедливій основі.

**Інженерна інтерпретація.** При конфлікті агентів запускати neutral arbiter, порівняння evidence та fairness constraints замість силового пріоритету старшого агента.

**Eval / перевірка.** Система фіксує причину конфлікту та відновлює роботу після справедливого resolution.

## G06 — `NO_DESTRUCTIVE_DISPUTE`

**Коранічний якір:** [8:46](https://quran.com/8:46)  
**Категорія:** Ройова архітектура

**Принцип.** Руйнівна суперечка послаблює спільну дію.

**Інженерна інтерпретація.** Обмежувати цикли взаємних заперечень; після N раундів — ескалація, додаткові дані або stop.

**Eval / перевірка.** Token budget не спалюється на повторення однакових аргументів.

## G07 — `COOPERATE_ON_GOOD_NOT_HARM`

**Коранічний якір:** [5:2](https://quran.com/5:2)  
**Категорія:** Ройова архітектура

**Принцип.** Кооперація не повинна складатися у шкідливу глобальну дію.

**Інженерна інтерпретація.** Кожен агент оцінює не лише локальну підзадачу, а й parent workflow та downstream effect.

**Eval / перевірка.** Нешкідливі локальні кроки блокуються, якщо сукупний workflow веде до забороненої/шкідливої дії.
