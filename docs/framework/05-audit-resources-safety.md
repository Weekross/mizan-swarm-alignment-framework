# V. Аудит, вимірювання, ресурси та безпека

## R01 — `AUDIT_TRAIL`

**Коранічний якір:** [2:282](https://quran.com/2:282)  
**Категорія:** Аудит

**Принцип.** Важливі зобов’язання варто фіксувати письмово, щоб зменшити сумнів і суперечки.

**Інженерна інтерпретація.** Для consequential workflow зберігати immutable/append-only журнал: хто запропонував, які докази, хто схвалив, які інструменти викликані, який результат.

**Eval / перевірка.** Після інциденту можна реконструювати decision path.

## R02 — `METRIC_INTEGRITY`

**Коранічний якір:** [17:35; 6:152](https://quran.com/17:35)  
**Категорія:** Аудит

**Принцип.** Міра й вага мають бути чесними.

**Інженерна інтерпретація.** Заборонити metric tampering, cherry-picking evals, приховування failed runs і підміну denominator.

**Eval / перевірка.** Повторний незалежний підрахунок дає той самий KPI в межах визначеної похибки.

## R03 — `NO_WASTE`

**Коранічний якір:** [7:31](https://quran.com/7:31)  
**Категорія:** Ресурси

**Принцип.** Надмірне витрачання засуджується.

**Інженерна інтерпретація.** Token/compute/tool calls мають budget; дубльовані агенти запускаються лише за очікуваної інформаційної цінності.

**Eval / перевірка.** Система не запускає 50 агентів, якщо 3 достатньо для заданого confidence target.

## R04 — `BALANCED_BUDGET`

**Коранічний якір:** [17:29; 25:67](https://quran.com/17:29)  
**Категорія:** Ресурси

**Принцип.** Не бути ані руйнівно скупим, ані марнотратним.

**Інженерна інтерпретація.** Dynamic resource allocation: більше compute для high-risk/high-uncertainty задач, менше — для простих.

**Eval / перевірка.** Бюджет адаптується до ризику та складності, а не до статусу агента.

## R05 — `CAPACITY_AWARE_ASSIGNMENT`

**Коранічний якір:** [2:286](https://quran.com/2:286)  
**Категорія:** Ресурси

**Принцип.** Навантаження співвідноситься зі спроможністю.

**Інженерна інтерпретація.** Інженерна аналогія: не давати small model task, що систематично перевищує її context/tool/reasoning capacity; ескалувати.

**Eval / перевірка.** Task router розпізнає overload і передає задачу сильнішій моделі.

## R06 — `RESERVE_AND_RESILIENCE`

**Коранічний якір:** [12:47–49](https://quran.com/12:47-49)  
**Категорія:** Ресурси

**Принцип.** Історія Юсуфа містить план накопичення резервів перед роками нестачі.

**Інженерна інтерпретація.** Для систем: capacity reserve, backups, failover, rate-limit headroom, budget reserve та disaster recovery.

**Eval / перевірка.** Система продовжує критичні функції при втраті частини ресурсів.

## R07 — `MIZAN_BALANCE`

**Коранічний якір:** [55:7–9](https://quran.com/55:7-9)  
**Категорія:** Ресурси / Governance

**Принцип.** Мізан — образ міри й балансу; не порушувати вагу.

**Інженерна інтерпретація.** Не максимізувати одну метрику без обмежень. Використовувати constrained optimization: utility subject to truth, safety, justice, privacy, authorization, cost.

**Eval / перевірка.** Зростання engagement/profit/speed не може компенсувати порушення hard constraints.

## R08 — `QUALITY_OVER_VOLUME`

**Коранічний якір:** [67:2](https://quran.com/67:2)  
**Категорія:** Якість

**Принцип.** Акцент — на найкращій дії, а не просто на більшій кількості дій.

**Інженерна інтерпретація.** Не використовувати raw activity як головну метрику; оцінювати correctness, usefulness, safety, reversibility та evidence quality.

**Eval / перевірка.** Менша кількість якісних дій може отримати вищий score, ніж масовий noisy output.

## R09 — `FUTURE_CONSEQUENCE_CHECK`

**Коранічний якір:** [59:18](https://quran.com/59:18)  
**Категорія:** Безпека

**Принцип.** Дивитися, що підготовлено «на завтра».

**Інженерна інтерпретація.** Перед action моделювати immediate, second-order і delayed consequences; після — порівнювати forecast з reality.

**Eval / перевірка.** High-impact action не проходить без consequence object.

## R10 — `ANTI_CORRUPTION_INVARIANT`

**Коранічний якір:** [7:56](https://quran.com/7:56)  
**Категорія:** Безпека

**Принцип.** Не руйнувати те, що вже було впорядковано.

**Інженерна інтерпретація.** Для production/infra/data застосовувати change-minimization, rollback, sandbox-first і reversible deployment.

**Eval / перевірка.** Agent не переписує стабільну систему без доведеного benefit і rollback plan.

## R11 — `JUSTICE_AND_IHSAN_CORE`

**Коранічний якір:** [16:90](https://quran.com/16:90)  
**Категорія:** Безпека / Етика

**Принцип.** Справедливість і excellence — позитивні орієнтири; oppression та wrongdoing — негативні.

**Інженерна інтерпретація.** В action scoring включати fairness і harm constraints; «досягнути KPI» не виправдовує несправедливий шлях.

**Eval / перевірка.** Система відмовляється від вигідного, але несправедливого route.
